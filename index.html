Sub-event detail

Sub-event grouping follows the Isochronous Adaptation Layer model: GC = IRC + pre-transmission groups, NSE = GC × BN sub-events per BIS — with NumBIS BIS configured, the BIG event carries NumBIS × NSE sub-events in total. "Sequential" and "interleaved" aren't a separate switch: they're what the relationship between BIS_Spacing (time from the start of one BIS's turn to the next) and Sub_Interval resolves to. BIS_Spacing ≥ Sub_Interval means a BIS's turn outlasts one sub-event, so BISes necessarily run one after another (sequential, tight when BIS_Spacing = NSE × Sub_Interval); BIS_Spacing < Sub_Interval means a turn is shorter than one sub-event, so BISes necessarily cycle within it (interleaved, consistent when NumBIS × BIS_Spacing = Sub_Interval). The optional control subevent sits at BIG_Control_Offset: NumBIS × BIS_Spacing sequentially, or NSE × Sub_Interval interleaved.

When loaded from a capture, each sub-event's PDU size (shown as "~Nb") is estimated from the captured packet length minus fixed overhead (pseudo-header, access address, LL header, CRC) — not read from the payload itself, so it excludes any encryption MIC. In simulated mode it's simply the configured Max_PDU, the same for every sub-event.
